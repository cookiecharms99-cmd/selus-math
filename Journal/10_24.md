## 🍪 Scratchpad

- Implemented `Vector::operator+`.
- Addition returns a new `Vector` rather than modifying either operand.
- Both operands only need to be read, so they can be treated as const.
- `const Vector& other` means `other` can be read without copying or modifying it.
- The trailing `const` on `operator+` promises not to modify the left-hand operand (`*this`).
- A `const Vector&` parameter can accept both const and non-const vectors.
- If vector dimensions disagree, there is no sensible vector to return. Throwing `std::invalid_argument` lets the function report failure without inventing a bogus result.
- Tested vector addition and deliberately tested mismatched dimensions.
- Learned that an overloaded binary operator can sometimes be either a member function or a free function.
- With a member operator, `a + b` can be understood roughly as `a.operator+(b)`, where `a` is `*this`.
- With a free operator, both operands are explicit: `operator+(a, b)`.
- Free functions can be especially useful for symmetric mathematical operations and mixed operand types, such as eventually supporting both `v * 2.0` and `2.0 * v`.

## 🌙 End-of-Session Note

**What I built:**  
I taught Selus vectors how to add! `a + b` now produces a new vector containing the element-wise sum while leaving the original vectors unchanged. I also added deliberate handling for vectors with incompatible dimensions.

**What I learned:**  
I learned how binary operator overloading works and how `const` applies to both operands of a member operator. I also learned why passing a vector as `const Vector&` lets us read it without copying it, while still accepting both const and non-const arguments.

I got my first practical introduction to exceptions: when an operation cannot produce a meaningful result, such as adding vectors with different dimensions, it can `throw` rather than return a fake value.

Finally, I learned the distinction between member and free operator overloads. A member operator treats the left operand as `*this`, while a free operator receives both operands explicitly. Neither approach is universally correct, and free operators can be useful when the operation is naturally symmetric.
